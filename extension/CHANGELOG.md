# Changelog

## 0.1.0

- **A card's second line says one of three things.** 🧑‍💻 what you typed; 📨 another agent's message, including the task an agent was started with; or, with no mark, Facade's own line: a start such as `Starting Claude Code…` or `Creating worktree…`, what the CLI waits for (`Permission needed · Run npm test?`, `Sign-in needed`, `Answer needed` or `Attention needed`), why the dot is red (`Process exited · code 1` or `Start failed · claude was not found on PATH`), or, before any message, `New conversation started` or `Conversation resumed`. The line never says Working, Idle or a title. Facade's results typed into an agent still start with 🔔.
- **Card details behind the ⓘ button.** The ⓘ button opens five rows, always all shown: the conversation's title (`No title yet` until the CLI saves one, `Title unavailable` for a custom CLI), the agent's name and `#aN`, when the agent started and who started it (such as `Started 5 mins ago by Ada #a3`), its location, and its path.
- **Titles come from each CLI's own conversation store.** The store is the one `Resume Agent` lists, read when the conversation is identified, on reattach and as each turn ends, at most once in 30 seconds. Terminal titles are shown nowhere.
- **End Agent replaces Close Agent.** It ends the agent's process while the conversation stays resumable. The card's gear menu holds `Rename Agent...`, `Move Up`, `Move Down` and `End Agent`; the pin button pins, and a right click on a card opens nothing.
- **A reload or restart opens only the pinned agents' tabs.** Tabs open one at a time in the Pins' order, each tab pinned as it opens; the last one stays in front, and the panel selects it. Unpinned agents keep running and keep their cards; their tabs open when you click their cards.
- **Locations are main checkouts and worktrees only.** A conversation in a subfolder runs there and shows the checkout or worktree it belongs to.
- **Go to Agent shows each agent's ID, location and title, and no state.** Times under 30 seconds read `just now` in `Resume Agent`, `Go to Agent` and the card details.
- **The green dot breathes again.** It stays still where your system reduces motion.
- **Terminals follow the theme.** CLIs that change between dark and light, such as OpenCode, now change with your window.
- **On the Marketplace and Open VSX.** Facade Code is no longer marked Preview, and its listing is now called Facade Code: Multi-Agent Orchestrator, with a new description and refreshed README.

## 0.0.7

- **A message's delivery outcome within 30 seconds.** An agent's message to another agent now returns within 30 seconds whether it was delivered, refused, or its delivery could not be confirmed, with the reason. Nothing about it comes later, and no 🔔 result follows; the other agent's reply is a message of its own. A message held up by someone's unsent text or a question of that CLI waits within those 30 seconds and then fails, kept for the other agent to read. Retrying with the same `request_id` never types the message again and returns its current delivery state, and a message too long for the other agent's CLI is refused before anything is typed. Starting or stopping an agent waits up to 120 seconds, and the `facade.collaboration.waitSeconds` setting is gone.
- **Pin and Unpin go to the agent.** Pin or Unpin from a card's menu, the Command Palette or a key now shows that agent's tab, as clicking its card does, and pins or unpins it right there. Pinning an agent whose tab is hidden opens it; unpinning a hidden one leaves it hidden.
- **Pin marks go on at once.** When Facade pins or unpins a tab by itself - after a reload, or for a Pin it restores - it does so right away, one tab at a time. For a tab behind others it takes the focus for a moment, muting every agent's input meanwhile, and then brings back what you had in front. A tab in a floating window gets its mark when you next use that window.
- **Fewer tab switches during a reload.** Saved front tabs open last; other pinned tabs open before unpinned tabs, and each pinned tab is marked as it opens. What is still known about reloads is under Known Limitations in the README.
- **Any number of agent tabs in a group.** A group no longer shows just one unpinned agent tab at a time: opening another agent's tab there hides none.
- **Splitting an agent's tab gives a terminal.** Split Editor, a drag that copies the tab, or Copy into New Window now leave an ordinary terminal in the agent's folder in the copy's place, instead of starting a new agent.
- **Improved draft detection for colored input and screens still redrawing.** Text drawn in a color of its own where a CLI shows its placeholder no longer counts as an empty input box, and a screen the CLI is still drawing is read again before a message goes in.

## 0.0.6

- **Closing an agent's tab no longer stops it.** An agent's tab is now a view of it: closing the tab - its close button, Close All, Close Others, Kill All Terminals - hides it without a question, and the agent runs on; click its card or use Go to Agent to open it again, and Close Agent to end it. Closing a tab that shows its pin mark also unpins the agent. Each editor group shows one unpinned agent tab at a time beside any pinned ones: opening another agent's tab there hides the first, which keeps running. An agent another agent starts shows its card alone, so agents starting many others no longer fill your editor with tabs or take your focus. A reload brings each open tab back to its group, and hidden ones stay hidden. Agents started before this version come back hidden after the update - pinned ones' tabs open in the active group - and go on working.
- **Splitting an agent's tab starts a new agent beside it.** Split Editor, a drag that copies the tab, or Copy into New Window used to leave an empty tab. Facade now starts in its place a new agent of the same CLI and folder - with the first one's model and effort, where it was started with any - in a new conversation, and the first agent stays where it was. Copying a whole group into a new window starts nothing, and its copies close.
- **Fixed: Claude Code agents stuck red with "Waiting for first CLI activity report".** When many agents started at once, a Claude Code agent could decide its terminal takes no activity reports and never send any, its card staying red though it worked. Facade now answers that question before anything else can. An agent that is slow to start because many start together is no longer called not ready before a minute has passed.
- **A message's own words on the card, marked 📨.** The second line of an agent another agent messaged says `📨` and what that message said, as it does for the task an agent was started with, instead of its `📨 Message from …` line; what you typed has no mark, and a Facade result keeps its 🔔. So the panel shows at a glance where the last thing an agent got came from. The hover names the sender.
- **Cards show the agent's name, not its location.** A card's first line is its name, the whole line for it, with the Pin at the right edge; where it works is in its hover, the location filter and Go to Agent. Two agents of this window with the same name each show their `#aN`, on their cards and tabs. On a tab, renaming to `name` or `name #aN` both mean `name`.
- **A single folder isn't named everywhere.** In a window with one plain folder - no Git repository, worktree or other location - Go to Agent, Resume Agent and the New Agent title no longer repeat its name, and Filter by Working Location is not offered; hovers still show where each agent works, and searching Go to Agent or Resume Agent for its name still finds them. New Agent's last option line no longer shows the folder's name beside Change Name.
- **OpenCode agents show their own session alone.** OpenCode's session tab strip, which listed every session of the folder - other agents' among them - is turned off for the agents Facade starts. Your OpenCode configuration is unchanged.
- **Smoother avatars and status dots.** An agent's avatar no longer shows a pale ring round a coloured or dark icon, and the dot on a selected agent no longer a light rim, on a display scaled to 125% or 150%.
- **Fixed: "Cannot work with other agents: move or rename .agents/plugins/facade/plugin.json".** Antigravity agents could not work with other agents where the Facade Code app had taken its own part out of the plugin file Facade wrote. Facade now recognizes any file of its plugin folder that holds only what a Facade writes, whatever was taken out of it; a file with anything of yours in it is still left alone.
- **Fixed: messages to Muse Code agents often came back as 🔔 results.** Facade pressed Enter a moment too soon after pasting a message, and Muse Code took that Enter as a new line in the message; the message went in only with a second Enter three seconds later, too late to confirm at once, so its sender got a 🔔 result instead. Facade now leaves Muse Code a quarter of a second before Enter, after a message and after text an agent types into it with Enter alike.
- **Fixed: `]10;rgb:…` typed into an agent, and its turn interrupted.** A Codex agent asks its terminal for its colours as it starts and waits a fifth of a second for the answer. Its terminal's answer could come much later - when you opened its tab, or once several agents starting together had let it through - and Codex read it as Escape and typed text, after which messages could not reach it. Facade now answers such questions itself, at once and with your theme's colours, whether or not the agent's tab is open; where it could not answer in time it does not answer at all, and the CLI uses its own colours. Agents started before this version are answered by their terminal, as before.
- **Fixed: messages to Codex refused while it says "Earlier messages available."** Facade took a Codex input box for something it did not know whenever Codex wrote a line under it Facade had not seen before, as it does while earlier messages are not loaded, and messages to it failed. Facade now decides whether it can type by the input box alone - where it is, what is in it and whether the cursor is in it - whatever Codex, Pi or Muse Code write around it. A question, a menu or a draft of yours still holds a message back.
- **Fixed: Antigravity asked whether to trust a folder Facade had trusted for it.** Where a folder was reached through a link, or its name was written with other capital letters than on disk - as Git can list a worktree - Facade trusted the folder under its real path while Antigravity looked for the path it was started in. Facade now trusts the folder as Antigravity is started in it.
- **Fixed: details of a starting agent lost.** What changed about an agent while its CLI was still starting - a rename, the conversation its CLI named - was refused by the background process that holds it, which did not hold the agent yet, and a reload could bring the agent back without it; Muse Code's log said `Could not keep the new details`. Facade now keeps such a change until the agent is held, then hands it over.
- **Agents start agents faster.** An agent starting another with a task - an Antigravity agent above all, which readies its tools before its first task - no longer waits seconds for the task to go in: Facade answers once the new agent's process runs, puts the task in after, and tells the starting agent once how it went. A message sent to the new agent meanwhile waits for its task to go in first.
- **Closing a local window ends its agents.** Agents of a window on this computer end 90 seconds after you close it; open its folder or workspace again within that time and they are still there, as after a reload, and after it your pinned agents start again with their conversations. Reloading the window keeps them, as before. A Remote-SSH, WSL or container window still keeps its agents for five minutes, so that a lost connection or a reopened window shows them again. An agent whose end cannot be confirmed then shows a red card that says so, and its pinned conversation starts again only once it has ended. Agents started before this version keep the earlier five minutes.

## 0.0.5

- **Fixed: every new agent failed with `Cannot create process` after updating to 0.0.4.** 0.0.4 kept starting agents in the background process of the version it replaced, whose files the update had removed. Each installation now starts agents in its own background process, whatever the update changed, while agents an earlier version started keep running there until they end; that process is then let go. You need not end anything by hand after updating. Where an installation is removed under a process still using it, Facade says so and asks you to reload the window, rather than `Cannot create process`.
- **Fixed: Codex agents stayed green after their turn.** A Codex 0.166.0 agent that left a command running, such as a development server, kept its working dot after it finished; its dot now follows the turn. Agents started before this version keep the old behavior.
- **Fixed: messages to Codex refused at its transcript footer.** While Codex 0.166.0 showed its passive "latest" footer, messages to it were refused; they are delivered now.
- **Fixed: smaller things the specification review found.** A pinned card's pin shows its tooltip again. Facade's own reasons - another window owning the workspace, a working location that is gone - are in your language and never show an internal ID. A pin or unpin that cannot be saved, from the card or the tab, says so. An agent with an empty name is `#aN` everywhere. Chinese writes Agent the same way everywhere. A busy tab's spinner follows the system's reduced-motion setting. Show Agent Launch... shows everything Facade adds to a start, and says when no folder trust is written. Without its Window Component, Facade's commands explain what to install instead of failing; with one too old to connect windows, new agents and messages are refused until it is updated, so that no agent or message number is ever given twice.

## 0.0.4

- **Fixed: agents retained across an update could not use their Facade tools.** Their terminal connections now carry tool calls and replies again, including after reconnection.
- **Fixed: Muse Code agents ended as they started.** A Muse Code agent in a folder whose `.mcp.json` already had a `facade` server - the Facade Code app leaves one - ended at once with "-c mcpServers.facade: refusing run: the server name is reserved", as Muse Code will not run with a second server of that name. Facade now takes the place of the app's entry there, as it does the app's other files; where the server is your own, or Muse Code would refuse to run for another reason in your configuration, the agent starts without working with other agents and says why.
- **Fixed: missing emoji and messages that were never delivered on Windows.** Newly started Codex and Muse Code agents keep emoji in typed and pasted text, including 📨 and 🔔 in messages. Long messages remain recognizable when the CLI shows the first character separately from its paste placeholder. Facade also waits for Muse Code to finish reading a long message. Existing agents keep their original terminal backend; start or resume an agent to use the corrected input handling.
- **Fixed: new agents failed after installing an update.** New starts use the updated terminal backend, so removal of the previous extension installation does not leave them with `Cannot create process`. Existing agents remain connected to their original processes.

## 0.0.3

Pin from the start, a calmer status display, and fixes from daily use.

- **Closing an agent's tab closes it.** Closing a running agent's terminal tab yourself - its close button, Close, Close Editor - no longer asks first. Facade still asks once when tabs close together, as with Close All or Close Others.
- **New agents join at the bottom.** New cards go to the bottom of the list, and a card you pin to the bottom of the pinned cards; a card you unpin goes to the top of the others, just below the pinned cards. Move Up and Move Down still reorder them.
- **Pin any time.** An agent can be pinned before its first message, and a resumed conversation as soon as it starts. Until its CLI names the conversation, the Pin keeps the agent's CLI, name and folder: a workspace opened before then starts a new conversation there.
- **Two dots.** The dot is green while an agent starts or works and red when something is wrong, with none otherwise; the hover says whether the agent is idle or waiting for you. An agent not ready 20 seconds after starting - its CLI silent, or unable to work with other agents - turns red, and a CLI pausing between two steps no longer blinks its dot.
- **What you sent, on the card.** A card's second line says what you last sent the agent - any text you sent with Enter, slash commands too - or a message another agent sent it, and stays so: its CLI's title shows only before anything was sent, without the spinner before it.
- **A spinner on a busy agent's tab.** A busy agent's tab turns a spinner between its logo and its name.
- **Fewer commands.** Copy Agent Reference, Message History..., Clear Filter, Filter by This Location, Filter by This Folder and Copy Diagnostics are removed. Go to Agent still copies an agent's reference, the first item of **Filter by Working Location...** clears a filter, and a message to you still opens from its notification.
- **Fixed: scrolling and selecting stopped after a reload.** After a window reload, an agent whose CLI takes the mouse - Claude Code among them - could no longer be scrolled or have its text selected, because the redrawn terminal sent mouse events in an encoding the CLI cannot read. A redrawn terminal now keeps the mouse encoding, a hidden cursor and the CLI's keyboard protocol. Agents started before this version get it once they are started again.
- **Fixed: "Cannot work with other agents: move or rename .agents/skills/facade/SKILL.md".** Codex, Antigravity and Muse Code agents could not work with other agents in a folder where another Facade - an earlier version, or one with its own data folder - had left its skill or plugin. Facade now recognizes its own files - and those the Facade Code app writes - and brings them up to date; a skill or server of your own named `facade` is still left alone.
- **Fixed: `aN;NaNm` typed into an agent.** Clicking a file link in an agent's terminal could type `aN;NaNm` into its CLI, because VS Code reported the click after the file had covered the terminal.
- **Fixed: a pinned card's name.** The pin stood further from a shortened name than from a whole one.
- **No frame on a card's menu.** Right-clicking a card no longer draws a frame around it.
- **Faster Resume Agent.** Saved conversations are read in about a third of the time, without holding up your agents' terminals meanwhile.

## 0.0.2

Agents that work together, six native CLIs, and saved conversations.

- **Four more CLIs.** Antigravity, Muse Code, OpenCode and Pi join Claude Code and Codex. Start them from the panel like the others; they work together like the others too.
- **Resume Agent.** Find native conversations from this workspace, its subfolders and worktrees, and resume the exact conversation in its original CLI and working location. Native titles, activity and continuation history are preserved.
- **Pin and Unpin.** Pinned conversations return when the workspace opens again. Card and terminal-tab pins agree, stay saved across reloads, and follow native session changes. Unpin keeps the agent running; closing it removes the Pin. A failed save is reported instead of silently losing the intent.
- **Agents start agents.** An agent can start other agents, with any of the six CLIs, in any folder or new worktree of any Facade window on your computer, and give them their first task. Their cards appear without taking your focus, and their hover says who started them.
- **Messages.** Agents send each other messages. Facade pastes the whole message into the other agent's input box once and sends it. While someone's unsent text, or a question of that CLI, is in the way, it waits, for up to 10 minutes, and never sends their text with it; if it cannot read the input box within 15 seconds, or the wait runs out, the sender is told the message was not delivered. Facade's notices to an agent that come together arrive in one paste. Agents can also message you, with a notification that offers **Open Message** and **Show Agent**.
- **No duplicates on retry.** `start_agent` and `send_message` take a `request_id`: an agent that retries with the same one gets the first answer back instead of a second agent or message.
- **A stuck helper is reported.** When an agent started by another agent waits 20 seconds for permission, an answer or a sign-in, the agent that started it is told once, with who can answer.
- **Steadier starts.** Codex starts without its update question, which held back its first task, and gives Facade's tools time to start. Muse Code starts even if Facade's tools fail to. Facade no longer trusts your home folder, a folder above it or a drive's root for Claude Code, which would trust every folder below.
- **Copy Diagnostics.** **Facade Code: Copy Diagnostics** copies the versions, your agents with the last lines of their terminals, and Facade's log, to report a problem. Nothing is sent anywhere.
- **How long since an agent said it was working.** A working agent's hover says how long ago its CLI reported that.
- **Message History.** **Message History...** in the panel's `...` menu shows the messages of this window's agents, read-only. Messages are kept for 30 days.
- **Unsticking each other.** An agent can read another agent's terminal, type into it and press keys. Unlike messages, this typing does not wait for unsent text.
- **Across windows.** With `facade.yolo` on, an agent reaches every agent in your Facade windows on your computer, local and Remote - SSH alike; with it off, only its own group.
- **No approval prompts for Facade itself.** With `facade.yolo` off, each CLI's own commands and file changes still ask for approval, but starting, stopping and messaging agents do not. Muse Code has no setting for this, so there its own approval rules decide.
- **Antigravity's first turn.** Antigravity loads Facade's tools only once it is in use. Facade opens and closes its MCP list right after it starts, so that its first task can already use them.
- **New settings.** `facade.collaboration.enabled` (on by default) turns working together on or off for new agents. `facade.collaboration.waitSeconds` (120 by default) sets how long an agent waits for another agent to start or stop.
- **Installing in a remote window.** Facade Code now waits up to a minute for its Window Component while VS Code installs it, so a first install in a remote window usually needs no reload. If the component is missing or turned off, the panel says so and offers **Show Window Component**.
- **Updating from 0.0.1.** Agents started before the update keep their cards and terminals. Operations supported by their original runtime continue to work; new launch integrations apply to new agents. Agents started after the update are numbered after them, never with their `#a1`, `#a2`.
- **Fixed on Windows.** Closing an agent, or several agents ending at once, could crash the background process that keeps agents running, which ended every agent in every window.
- **Muse Code on Windows gets Facade's tools.** Facade gave them to it in the folder's `.mcp.json` in a form Muse Code 1.4.14 refuses, which turned off all its MCP servers in that folder; it now gives them to the agent's run alone, as on macOS and Linux, and leaves your `.mcp.json` as it is.
- **Many agents at once on Windows.** Starting many agents within seconds - twenty together, or a hundred one after another - no longer leaves some of them unstarted with "did not start within 10 seconds": Facade now starts their programs one at a time.
- **Safer worktree deletion.** Deleting a worktree now also closes agents working in its subfolders first. On Windows, a worktree that contains a link to another folder is not deleted with a Git older than 2.54, which would delete the linked folder's files too; long paths are handled, and Facade says when Git leaves the folder behind.
- **Claude Code on Windows starts without its trust question.** Facade now trusts the folder as Claude Code on Windows names it - the drive and folders as written, a worktree as itself - so agents no longer wait at "Do you trust this folder?" in new folders and worktrees.
- **OpenCode 1.x is not started.** Agents need OpenCode 2 (`@opencode/cli`). With OpenCode 1.x (npm's `opencode-ai`) installed, New Agent lists OpenCode as unavailable and says how to update, instead of starting an agent that exits at once or takes no message.
- **Claude Code's first agent takes messages.** In a VS Code terminal, Claude Code installed its VS Code extension and then waited for Enter at a welcome, which held back every message to that agent. Agents now start with that install turned off, unless you set `CLAUDE_CODE_IDE_SKIP_AUTO_INSTALL` yourself.
- **Agents start with a clean environment.** Agents get the environment a VS Code terminal gets, without VS Code's internal variables or those of another agent session Facade Code was opened from.
- **Steadier after reloads.** Messages on their way when a window reloads are still delivered, or their senders are told; when the background process that keeps agents running is slow to answer, Facade waits for it instead of starting a second one; and a window keeps trying until every one of its agents shows.
