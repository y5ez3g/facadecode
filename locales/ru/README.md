# Facade Code

**Одна IDE для вас и вашей ИИ-команды.**

Построена на VS Code. Запускает нативные CLI ваших агентов, например Claude Code, Codex, Antigravity и Muse Code.

Facade Code — это форк VS Code, в котором нативные агенты всех вендоров вместе работают над вашими проектами и фичами, а вы в том же окне ревьюите код и направляете любого из агентов.

- 🧑‍💻 **Полноценный VS Code, организованный по проектам и фичам.** Разрабатывайте несколько проектов и фич в одном окне. Каждая фича — это git worktree со своей командой агентов.
- 🤖 **Команда нативных CLI-агентов от разных вендоров.** Агенты работают на ваших собственных подписках. В Facade Code агенты запускают друг друга, обмениваются сообщениями и помогают друг другу, когда кто-то застрял.
- 👥 **Super Engineer или Super Team.** Управляйте несколькими агентами сами или назначьте ведущую модель, которая будет координировать параллельную работу специалистов.

## Установка

Скачайте последнюю версию в разделе [Releases](https://github.com/y5ez3g/facadecode/releases): `.dmg` для macOS (Apple silicon), установщик для Windows (x64) или `.deb` для Ubuntu (x64).

**Требования**: установите CLI агентов, которыми хотите пользоваться, и войдите в них (любое сочетание Claude Code, Codex, Antigravity и Muse Code). Facade Code запускает их напрямую, с их собственной авторизацией и подписками.

Facade Code устанавливается рядом с VS Code и ничего с ним не делит: настройки, расширения и консольная утилита `facade` полностью раздельны.

## Быстрый старт

1. **Откройте проект**:
   ```sh
   facade ~/code/space-shooter
   ```
   Или воспользуйтесь **File > Open Folder** (Файл > Открыть папку), или перетащите папку на панель рабочих пространств. Папка должна быть git-репозиторием (worktree требуют git; если начинаете с нуля, сначала выполните `git init`).

2. **Запустите техлида**:
   Нажмите на значок робота в строке заголовка (меню Agent) или выполните **Agents: Start Agent...** (запустить агента) в палитре команд и выберите Claude Code или Codex. Агент, запущенный из Facade Code, получает MCP-инструменты Facade.

3. **Дайте ему промпт для техлида**:
   ```text
   Ты техлид. С помощью Facade сделай для демо неоновый космический шутер для браузера
   (десктоп). В команде: PD на GPT Sol 6 (gpt-6-sol, max) через Codex, который отвечает
   за внешний вид и ощущения от игры, и три инженера на Muse 1.3 (muse-spark-1.3, max),
   работающие параллельно. Держи объём небольшим, примерно на полчаса работы: один
   уровень, три типа врагов, босс с двумя фазами, бонусы, очки и комбо. Лучше доделать
   и отполировать игру, чем добавлять фичи. Инженеры сами мержат свою работу, а ты потом
   ревьюишь. Пришли мне одну HTML-страницу с коротким планом, swimlane-диаграммой и
   макетом от PD и дождись моего одобрения, прежде чем начинать.
   ```

4. **Наблюдайте за работой команды**:
   Запущенные PD и инженеры появляются на панели рабочих пространств под своим проектом и фичей. Как только вы одобрите HTML-план, они начнут работу. В любой момент можно открыть терминал любого агента, чтобы посмотреть вывод или поговорить с ним напрямую.

*(Примечание: этот пример промпта запускает 5 агентов с максимальным уровнем рассуждений. Подберите CLI, модели, уровни рассуждений и число инженеров под ваши подписки.)*

## Возможности

### Проекты и фичи, а не сессии

https://github.com/user-attachments/assets/bf93be03-1c75-4d35-86ca-c2a62a62ea95

Большинство инструментов для агентов создают worktree на каждую сессию агента. Facade Code устроен наоборот: каждый worktree — это фича, она показана под своим репозиторием, а вы назначаете на неё агентов.

Фиче часто нужен не один агент. Тот, кто пишет код, может плохо объяснять свою работу или не иметь чутья к дизайну, поэтому другие агенты помогают с документацией, дизайном и ревью, и все они работают в том же worktree. Агенты приходят и уходят, а фича остаётся.

- **Панель рабочих пространств**: все репозитории и фичи в одной колонке. Щёлкните по одному из них, и всё окно (проводник, редакторы, терминалы и система управления версиями) переключится и восстановится в том виде, в каком вы его оставили. Проекты никогда не смешиваются. См. [`WORKSPACE.md`](../../facade-code-spec/WORKSPACE.md).
- **Жизненный цикл worktree**: **New Worktree** (новый worktree) создаёт ветку, синхронизирует локальные файлы из `.worktreeinclude` и выполняет начальную настройку. **Delete Worktree** (удалить worktree) перед удалением подробно показывает, что будет потеряно. См. [`WORKTREE.md`](../../facade-code-spec/WORKTREE.md).
- **Параллельные подзадачи**: независимые задачи можно вынести в отдельные worktree.

### Команда от всех вендоров

- **Нативные CLI на ваших подписках**: Claude Code, Codex, Muse Code и Antigravity работают в своих встроенных терминалах и используют подписки, которые у вас уже есть.
- **Агенты запускают агентов**: агент может запускать других агентов (с CLI или моделью любого вендора) в текущей фиче или в новом worktree и раздавать им задачи. См. [`AGENT-LAUNCHER.md`](../../facade-code-spec/AGENT-LAUNCHER.md) и [`AGENT-ORCHESTRATION.md`](../../facade-code-spec/AGENT-ORCHESTRATION.md).
- **Сообщения**: агенты пишут друг другу, отчитываются о результатах перед тем, кто их запустил, и сообщают вам, когда решение требует одобрения человека. См. [`AGENT-MESSAGES.md`](../../facade-code-spec/AGENT-MESSAGES.md).
- **Помогают друг другу**: агент может читать терминал другого агента, отвечать на его запросы и отправлять нажатия клавиш, чтобы выручить застрявшего инженера, не отвлекая вас. См. [`AGENT-DEBUGGING.md`](../../facade-code-spec/AGENT-DEBUGGING.md).
- **Вы можете вмешаться в работу любого**: у каждого агента есть своя строка терминала под его фичей. Вы видите, что он делает, и в любой момент можете печатать прямо в нём.
- **Стандартный MCP**: все инструменты оркестрации доступны через стандартный MCP-сервер.

## Два способа работать

Узкое место — внимание разработчика. Два режима — это два уровня делегирования:

| | **Super Engineer** | **Super Team** |
|---|---|---|
| **Ваша роль** | Инженер, который сам пишет код | Руководитель разработки |
| **С кем вы общаетесь** | Напрямую с несколькими агентами | С агентом-техлидом, один на один |
| **Кто координирует агентов** | Вы | Техлид |
| **Подходит для** | Фич, где нужно плотное сопровождение: исследовательская работа, дизайн-решения, которые вы хотите оценить сами, меняющиеся требования | Крупных, чётко определённых фич, которые хорошо делятся на части |

Оба режима можно сочетать в одном окне: держать под плотным контролем важные фичи и отдавать техлиду работу с ясными рамками.

- **Super Engineer**: вы сами открываете worktree, раздаёте задачи агентам в разных репозиториях и ревьюите код по мере того, как каждый заканчивает.
- **Super Team**: вы передаёте фичу агенту в роли техлида. Он разбивает работу на задачи, определяет контракты интерфейсов, запускает исполнителей и ревьюит их результат.
  - Ведёт сильная модель; более быстрые и дешёвые модели на ваших подписках параллельно пишут код; а модели разных вендоров ревьюят работу друг друга.
  - Чтобы всё это настроить, достаточно одного промпта (см. [Быстрый старт](#быстрый-старт)); командные процессы, к которым вы возвращаетесь, можно оформить как skills.

## Зачем

Большинство ИИ-инструментов для программирования делятся на два лагеря: IDE в стиле Copilot, где человек должен следить за каждой строкой, и агентные IDE, где ревью кода и отладку приходится выносить во внешний редактор. Ни те ни другие не собирают команду нативных агентов от разных вендоров внутри вашей основной IDE.

Мы верим, что будущее за разработчиком, который ведёт несколько проектов и фич с командой агентов. Разные модели сильны в разных задачах, поэтому команда должна включать разных вендоров. А раз код, который вы ревьюите, пишут агенты, этой команде место в вашей IDE.

## Всё ещё VS Code

Facade Code меняет только то, чего требует управление несколькими проектами и агентами:

- **Панель рабочих пространств** занимает первую колонку; **панель действий** переезжает в правый верхний угол строки заголовка (вернуть можно через `workbench.activityBar.location`).
- Copilot и чат из upstream по умолчанию отключены (одна настройка включает их обратно).
- Всё остальное — обычный VS Code: редактор, настройки, сочетания клавиш, `.vscode/` и файлы `.code-workspace`.
- Расширения устанавливаются из [Open VSX](https://open-vsx.org). Некоторые проприетарные расширения Microsoft, например Remote Development и C/C++, лицензированы только для официальных сборок Microsoft и не работают в форках.
